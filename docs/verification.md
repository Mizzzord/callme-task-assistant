> Дополнение от 30.10.2026: по новому поручению реализованы CallMe, аккаунты и совместная работа. Актуальные правила и проверка — [callme-team.md](callme-team.md). Указания ниже об отсутствии регистрации относятся к предыдущему этапу.
Последующее обновление канбана, проектов и связанных сервисов: **22 успешных теста**, итоговая сборка и новый браузерный прогон описаны в [kanban-and-services.md](kanban-and-services.md). Ниже сохранён отчёт первоначальной версии, включая её 16 тестов и старые снимки.

## Автоматические проверки

- `npm test`: **16 passed, 0 failed**. HTTP-сценарии используют реальный Express и SQLite во временной папке, фиксированное московское время и независимые cookie. Временные базы удаляются после теста.
- `npm run build`: успешно; TypeScript клиента, сервера и тестов + production-сборка Vite.
- `npm run lint`: exit 0, **9 предупреждений** в установленных shadcn-компонентах/хуке (React Fast Refresh exports и setState-in-effect). Правила не отключались. В прикладном коде предупреждений не осталось.
- `npm audit --omit=dev`: 3 low advisory-цепочки, связанные с `deepmerge` через CLI `shadcn`/`@shadcn/registry`. Автоматический downgrade/force-fix не применялся. Это отдельное ограничение инструментария; общий аудит безопасности проекта не проводился.
- Сборка отдана локальным `npm start` на http://127.0.0.1:3001/, HTTP 200. Браузер открыл собранную версию и восстановил прежнюю историю после перезапуска сервера. Vite dev-сервер остановлен.

Содержание тестов:

1. 1000 уникальных исходных ID, точные original-поля, сохранение повторяющихся названий, повторный импорт без восстановления удалённого/перезаписи изменённого.
2. Создание задачи текстом: дата без времени, без срока, время без даты → уточнение; напоминание без доставки.
3. Уточнение длительности встречи; конфликт → подтверждение; прошлое → отмена/подтверждение; несуществующая дата отвергается.
4. Совпадение начала исходной встречи с неизвестной длительностью; смежные известные интервалы не пересекаются.
5. Несколько результатов → выбор номером → «её» → перенос → выполнение → удаление с отменой и подтверждением.
6. Новая команда заменяет черновик; неуверенная речь не создаёт событие; подтверждение голосового уточнения сохраняет прежний черновик.
7. Конкурентные повторы с одинаковым requestId, запрет чужого ID, конфликт revision, устаревший токен подтверждения.
8. Фильтры периода, русские окончания в поиске, пустой результат, неправильное время.
9. Повторное открытие SQLite и история; запрет изменения без защитного заголовка; изоляция двух клиентов.
10. Глобальный резерв API не превышает настроенный лимит; неизвестная цена блокирует резерв.
11. Оборванная текстовая команда и неверные часы не создают запись; перенос исходной записи не снимает inferred.
12. Искусственная ошибка записи SQLite: событие не сохраняется и успех не возвращается.
13. Выбор номером и отмена через голосовой текст допустимы без изменения событий; создание требует проверки распознавания.
14. Московская полночь, переход года, завтра/послезавтра/через 2 часа, високосный февраль.
15. Текущая неделя заканчивается воскресеньем, следующий понедельник исключён.
16. Контракт YandexGPT с подменённым HTTP: JSON, версия из конфигурации, запрет модели подтверждать операции, таймаут; ошибка TTS не утверждает, что сохранение отменено.

**Внешние AI-вызовы в тестах не выполнялись.** Проверка подменённого ответа подтверждает локальный контракт, но не работоспособность аккаунта Yandex, стоимость, качество модели или речи.

## Проверка в настоящем браузере

Использован встроенный браузер Codex. Размеры: **1440×900** и **390×844**. Проверено DOM-измерением: scrollWidth совпадает с шириной viewport, горизонтального переполнения нет. Мобильная панель расписания занимает ширину экрана, форма и её действия видны, поле получает фокус. После финальной перезагрузки журнал браузера не содержал ошибок/предупреждений приложения.

Пройденные сценарии:

- «Создай задачу проверить прототип завтра» → сохранённое название и дата.
- «Создай встречу с дизайнером завтра в 16:00» → вопрос о длительности → «45 минут» → сохранённая встреча.
- Пустая форма → сообщение «Введите название записи»; задача без срока через форму → сохранение.
- Мобильная панель: пустой поиск → Empty → сброс → нахождение созданной записи.
- Открытие формы на телефоне → изменение названия → сохранение с подтверждёнными данными.
- «Отметь её выполненной» → подтверждённое выполнение выбранной задачи.
- «Удали её» → конкретная запись в AlertDialog → «Отмена» → запись остаётся. Финальное удаление проверено API-тестом, а не в этом ручном UI-сценарии.
- Перезагрузка и перезапуск сервера → история и данные доступны.
- Enter отправляет реплику; «Покажи планы на завтра» → два реальных результата; выбор второго кнопкой → контекст выбранной встречи.
- Недоступный голосовой сервис → понятная ошибка и доступный текстовый ввод.
- Приостановлен только собственный локальный API-процесс. Отправка → loading → таймаут 25 секунд → «Результат действия неизвестен». Сервер возобновлён; «Повторить» → сохранённый результат. В SQLite **одна** запись с названием «повтор без дубля».
- Ошибка начальной загрузки во время перезапуска → «Повторить загрузку» → восстановленное пространство.

Снимки: [десктоп](screenshots/desktop.jpg), [мобильный экран](screenshots/mobile.jpg).

В тестовом браузерном пространстве оставлены пять записей, созданных в ходе проверки; новое пространство получает только исходные 1000 событий. Пользовательские данные из других проектов не импортировались.

## Найденные и исправленные проблемы

- TypeScript 7 больше не принимает baseUrl из шаблона: оставлены относительные paths.
- Подтверждение голосового уточнения теряло предыдущий черновик: добавлено сохранение prior-контекста и регрессионный тест.
- Форма редактирования первоначально включала служебные поля в payload: теперь отправляются только Draft-поля, ID и revision. Повторно проверено в браузере.
- InputGroup визуально отключал весь ввод из-за disabled-кнопки отправки: состояние ограничено основным полем. Проверены вычисленные opacity=1 и disabled=false для голосовой кнопки.
- Мобильный Sheet наследовал ширину 3/4: исправлен layout для полного экрана.
- Классификация исходного типа по вхождению слова «встреча» заменена проверкой начала фразы, чтобы «Отправить итоги встречи» не считалось встречей.
- Локальный обработчик не сохраняет явно оборванную фразу «… завтра в» и ошибочное время 25:00.

## Не проверено

Физический микрофон и его отказ, реальная STT/TTS, качество русской речи, перебивание и эхо, реальные мобильные устройства/Safari, живой YandexGPT, актуальность доступа и тарифов, фактический биллинг, публичный HTTPS и многопроцессный режим. Конкретные ограничения и покрытие всех историй перечислены в `requirements.md`.
